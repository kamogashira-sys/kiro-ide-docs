## 🔷 0.1（Preview release）

**リリース日**: 2025-07-14
**公式ページ**: <https://kiro.dev/changelog/ide/0-1/>

Kiro の最初の公開版です。公式の紹介文は「**仕様駆動開発（spec-driven development）で最良の仕事をするための、新しいエージェント型 IDE**」です。この時点で次の5つの柱が揃っていました。

| 機能 | 公式の説明 |
|------|----------|
| **Specs** | アプリケーションの複雑な機能について、開発プロセスを形式化する構造化された成果物 |
| **Hooks** | ファイル保存などのイベントで、ドキュメント更新やテスト生成といったイベント駆動の自動化を設定できる |
| **Steering** | エージェントの振る舞いを導く Steering ファイルを定義できる |
| **Agentic chat** | チャットから機能を構築する。Autopilot モードで自動実行するか、変更を1つずつ手で承認する |
| **MCP** | 使い慣れたツールやサービスと連携する |

> この5つは現在も Kiro IDE の中核機能です。最新仕様は [機能詳細ガイド](../01_features/) を参照してください。

## 🔹 0.2.13

**リリース日**: 2025-08-15
**公式ページ**: <https://kiro.dev/changelog/ide/0-2-13/>

アクセシビリティ・アカウント管理・プラットフォーム全体の信頼性を改善したリリースです。

- **🎟️ ウェイトリストコードの対応**: ウェイトリストコードを持っていれば登録して利用を開始できるようになった
- **💳 有料プランの提供開始**: より高い使用量上限にアクセスできる有料プランが利用可能に
- **📊 使用量の追跡と請求ダッシュボード**: Spec / Vibe のリクエスト使用量をリアルタイムに表示し、プラン管理と超過分の制御を提供

### 改善

- **コマンド信頼の強化**: パイプを含むコマンド（`ls -la | grep ".js"` など）の扱いを改善し、コマンドチェーンに対する信頼の要件を明確化
- **ワークスペースの保護**: ファイルシステムツールの制限を改善し、外部への誤った変更を防ぎやすくした
- **コマンドの境界**: 危険な可能性のあるパターンを含むコマンドは、明示的に信頼していない限り手動承認を必要とするようになった
- **自動再試行**: バックエンドへのリクエストが失敗した場合に自動で再試行されるようになった
- **モデル効率の最適化**: Sonnet でのフロンティアモデルの使用を最適化
- **ライトモードの改善**: テーマ関連の問題を解消し、視覚的な一貫性を向上
- **ログインエラーの明確化**: 認証失敗時のエラーメッセージをより有用な内容に

## 🔹 0.2.38

**リリース日**: 2025-09-04
**公式ページ**: <https://kiro.dev/changelog/ide/0-2-38/>

エディタの性能改善・信頼性向上・不具合修正を含むリリースです。

### 性能と信頼性

- **Code OSS v1.100.3 へのアップグレード**: 安定性と性能が向上
- **応答時間の短縮**: リクエスト処理の最適化により、やり取りが効率化
- **セッション管理の改善**: バックエンド処理の強化により中断が減り、より長く継続して作業できるように

### 利用体験の向上

- **ツール呼び出しの回復の強化**: ツールの呼び出しが繰り返し失敗した場合、無制限に続けるのではなく利用者の介入を求めるようになった（使用量上限の保護とループの防止）
- **セキュリティパターンの強化**: 危険なシェルコマンドの検出を、パターン認識の改善により拡張。リスクのあるコマンドは明示的に信頼しない限り手動レビューを要する
- **モデルの更新**: モデルセレクターから Claude Sonnet 3.7 を削除し、全利用者の既定を Claude Sonnet 4 に設定

### 修正

- **Git リポジトリの初期化**: リポジトリのない新規プロジェクトで Git のセットアップができない問題
- **モデル選択の永続化**: Kiro IDE の再起動時にチャットのモデル選択が保存されない問題

- **Git コミットメッセージの生成**: ソース管理ペインからワンクリックで、エージェントによるコミットメッセージの下書きを作成できる

- **長時間実行コマンド**: `executeBash` ツールが、開発サーバー・テストランナー・対話型コマンドなどを検知して回避するように
- **使用量メーター**: 同一セッション内でアカウントを切り替えたときに正しく更新されるように

- **コンテキストポップアップの位置**: チャットで `#` を入力したときのポップアップの位置を改善（入力欄コンテナの左上に一貫して表示）
- **テーマの互換性**: Light High Contrast・Kiro Light・Light+・Quiet Light のテーマで、超過分のトグルの視認性とアカウントダッシュボードへのアクセスを改善

### 修正

- **リモートワークスペースの信頼性**: リモートホストに接続する際、信頼していないワークスペースでの拡張機能の読み込みの問題

## 🔷 0.4

**リリース日**: 2025-10-15
**公式ページ**: <https://kiro.dev/changelog/ide/0-4/>

バックグラウンドプロセスによる開発サーバー対応、Spec のコンテキストプロバイダーと MVP タスクのワークフロー、MCP の制御強化、プロンプト単位の使用量追跡と通知を導入しました。

### 主な新機能

- **Spec の MVP タスクの UX**: Spec 作成時に開発のペースを選べる。エージェントがタスクを生成する際「Keep optional tasks (faster MVP)」を選ぶとテストとドキュメントが任意（✱）になり、「Make all tasks required」を選ぶと最初から網羅的になる。任意のタスクはワークフロー全体で表示され続ける
- **チャットでの Spec のコンテキスト**: チャットで `#spec` を使って Spec ファイルを直接参照できる。エージェントが Spec の文脈を理解し、開発中の応答がより正確になる
- **開発サーバーのサポート**: `npm run dev`・ビルドの watcher・テストランナーなどの長時間コマンドが自動でバックグラウンド起動する。エージェントがこれらを検知して即座に制御を返し、追跡を継続する（ターミナルが塞がらない）
- **プロンプト単位のクレジット消費の可視化**: 各プロンプトが消費したクレジット数をチャットパネルで確認できる
- **先回りした使用量の通知**: クレジット使用の傾向について通知を受け取り、想定外の事態を避けられる

### 改善

- **テストカバレッジの改善**: 過剰なテストファイルではなく、焦点の合った意味のあるテストを生成するように
- **より簡潔な応答**: プロンプトの改良により、エージェントがより直接的で要点を突いた応答をするようになった
- **リポジトリの安全性**: Supervised モードで、エージェントが `.git` ディレクトリへの書き込みを自動的に避けるように
- **MCP サーバーパネルの強化**: 個別のツールの有効・無効の切り替えと、成功の表示を一目で確認できる操作を追加
- **モーダルの操作の整理**: モーダルが他のキー入力をブロックし、Escape またはクリックでのみ閉じるようになった
- **請求の通知**: 通知設定から請求のオプションに直接アクセスできるように
- **使用量メーター**: サインイン時やアカウント切り替え時にステータスバーのメーターが正しく更新されるように
- **使用量の要約**: 設定で実行時の使用量の要約を無効化できる

### 修正

### Powers

Kiro のエージェントに、任意のフレームワークやツールの専門性を即座に与える新しい仕組みです。

### 要約（Summarization）

### スラッシュコマンド

チャット入力から、フックと Steering ファイルに素早くアクセスできます。

- `/` を入力すると利用可能なコマンドが表示され、即座に実行できる
- **手動トリガーのフック**と、**手動include に設定した Steering ファイル**がスラッシュコマンドのメニューに現れる
- テストの実行・ドキュメントの同期・特定のガイダンスの取り込みを必要に応じて行える

> **注意**: 1.0 では manual hooks が廃止され、manual steering ファイルに置き換えられています。
> また **Kiro IDE のスラッシュコマンドはユーザー定義**であり、Kiro CLI 版のスラッシュコマンド（製品が提供する固定リスト）とは仕組みが異なります。

- **Supervised モードの強化**: 複数ファイルを変更する際に、**ファイル単位で個別にレビューして選択的に受け入れ・拒否**できる。ターンベースのこの方式は vibe チャットと Spec チャットの両方で機能する

- **`.kiroignore` のサポート**: gitignore の構文でエージェントのアクセスからファイルを除外できる。プロジェクトルートに `.kiroignore` を作り、`agentIgnoreFiles` 設定に追加する

- **メッセージのコピー**: 新しいコピーボタンでエージェントの応答をワンクリックでコピーできる
- **モデルのドロップダウン**: Escape でモデル選択のドロップダウンを閉じられる
- **Spec の名称変更**: Kiro パネルから直接 Spec の名前を変更できる

## 🔷 0.10

**リリース日**: 2026-02-18
**公式ページ**: <https://kiro.dev/changelog/ide/0-10/>

アーキテクチャから設計を始められる新しい Spec ワークフローと、構造化された根本原因分析で不具合を修正するワークフローを導入しました。Supervised モードは hunk 単位でのレビューに対応します。

### 主な新機能

- **Design-First の機能 Spec**: 要件ではなく技術アーキテクチャから機能 Spec を始められる新しいワークフロー。高レベル・低レベルの設計・擬似コード・システム図を与えると、Kiro が実現可能な要件を導出する。**厳しい非機能要件がある場合、既存の設計を移植する場合、利用者向けの振る舞いを定義する前にアーキテクチャを検討したい場合**に適する
- **Bugfix Spec**: Spec に不具合修正専用のワークフローが加わった。見えている問題を説明すると、Kiro が根本原因分析・修正の設計・再発防止を案内する。結果として現在の挙動・期待される挙動・変えてはならない箇所を記録した `bugfix.md` が得られ、エージェントが1行も書く前に明確なガードレールを与えられる
- **Supervised モードの hunk 単位レビュー**: ファイル全体の差分ではなく、**個別の hunk（関連する行の論理的なまとまり）**として変更が提示される。各 hunk を独立して受け入れ・拒否・インラインチャットで相談できる。ファイル単位や一括での受け入れも可能
- **Pre / Post Task Execution フック**: Spec のタスク実行の前後を自動化する2つの新しいトリガー。**Pre Task Execution** はタスク開始前に発火するのでセットアップスクリプトの実行や前提条件の検証ができる。**Post Task Execution** はタスク完了後に発火し、テスト・lint の実行や外部システムへの通知を自動化できる
- **MCP のプロンプト・リソーステンプレート・elicitation**: MCP サーバーがチャットのコンテキストプロバイダー（`#`）メニューに現れるプロンプトとリソーステンプレートを提供できるようになった。プロンプトを選ぶと事前に用意された指示が挿入され、リソーステンプレートのパラメータを埋めると特定の内容をコンテキストとして取り込める。ツール実行中にサーバーが **elicitation** を通じて追加の入力を求めることもできる

### 改善

- **スキルと Steering**: スキルと自動include の Steering ファイルを、チャットのスラッシュコマンドから有効化できるように
- **会話のエクスポート**: 会話をエクスポートする際にサブエージェントの実行も含まれるように
- **フック作成の UI**: フック作成フォームに Save と Clear のボタンを追加。手動でのフック作成フローと、フック検出のための再帰的なフォルダ展開も追加
- **フックのパネル**: フックのエクスプローラーのコンテキストメニューから直接フックを削除できる
- **フックの時間制限**: `runCommand` のフックが時間制限の設定に対応
- **ターミナルの入力待ちの検知**: ターミナルのコマンドが利用者の入力を待っていることを検知し、UI に警告を表示する
- **コードツール**: 構文の検証・自動修復・より厳密なあいまい一致を改善し、コードの編集の信頼性を向上
- **Spec の Continue ボタン**: Spec のナビバーの Continue ボタンで、コンテキストを切り替えずに Spec の各段階を進められる
- **Spec のプレビュー**: Markdown の Spec ファイル用のフローティングのプレビューボタンを追加
- **Web 取得**: content-type の扱いを改善し、より広範なページに対応
- **Markdown の描画**: チャットでの Markdown のストリーミングを改善

### 修正

## 🔷 0.12

**リリース日**: 2026-05-06
**公式ページ**: <https://kiro.dev/changelog/ide/0-12/>

公式の言葉では「**Kiro Specs を、始めるのも終わらせるのも速くし、間違えにくくする**」リリースです。独立したタスクを並列実行し、範囲が分かっているときは Quick Plan で承認のゲートを省略でき、要件の論理的な矛盾を実装の問題になる前に捕まえられます。

### 主な新機能

- **タスクの並列実行**: Run all Tasks が独立したタスクを1つずつではなく**並列に**実行するようになった。設定は不要で、Kiro がタスク一覧の依存関係を分析し、独立したタスクを並列の「波」にまとめ、それぞれを独立したコンテキストで実行する。**独立したタスクが4つ以上ある Spec では実行時間を最大4分の1に短縮できる**
- **Quick Plan**: 何を作るかが既に分かっている場合の新しい Spec セッションのモード。段階間の承認ゲートなしで、requirements・design・tasks を一度に生成する。最初に確認事項（範囲・制約・エッジケース）を尋ね、その後3つの成果物を生成してタスク一覧に直接到達する。**Specs と同じ追跡可能性と正しさを保ちながら、フィードバックのループをより短くする**
- **要件の分析（Analyze Requirements）**: 設計に進む前に、要件の論理的な矛盾・あいまいさ・相反する制約・欠落を捕まえる深い分析。Kiro が自動推論を使い、読み通すだけでは捕まえにくい問題（あいまいな表現・相反する制約・論理の欠落）を見つける。結果はチャットに確認の質問として現れ、短時間で解消できる

### 改善

- **コマンドパレット**: VS Code 標準の位置に戻り、タイトルバー経由のドラッグ＆ドロップに対応
- **Kiro Light テーマ**: ステータスバーの項目に濃い灰色の背景が表示されなくなった
- **Sync Files**: `tasks.md` の Update tasks ボタンを Sync Files に名称変更
- **拡張機能ホストのクラッシュからの回復**: 一時的な障害では自動で再起動する。クラッシュが繰り返される場合は明確な案内とともに「Restart Kiro」のアクションが表示される

### 修正

- 拡張機能ホストの分離後にソース管理パネルが「no folders containing Git」と表示する問題
- 専用の拡張機能ホストでの Generate Commit Message とブランチ検出の問題
- Supervised モードでターンごとの承認のスナックバーが表示されない問題
- 以前のバージョンからアップグレードした後にコマンドパレットの位置が想定外になる問題

### ▫️ 0.12 系のパッチ

**0.12.292**（2026-06-04）— チャットに適応的な思考の深さの制御、MCP サーバーの一括管理、シェルの引用符による停止からのターミナルの自動復旧を追加。

*適応的な思考の制御*

各応答にモデルがどれだけの推論を投じるかを選べます。モデルセレクターの隣の新しい effort のドロップダウンからレベル（low → max）を選び、`auto` に切り替えることもできます。難しい問題では上げ、素早い反復では下げられます。モデルを切り替えても可能な限り設定が保たれ（無効なレベルは新しいモデルで最も近いものに合わせられる）、effort は**ワークスペース単位で永続化**されます。

*MCP ツールの一括切り替え*

MCP Servers パネルの新しいツールバーのボタンで、すべての MCP サーバーとそのツールを一度に有効化・無効化できます。**Enable All** は無効化されたサーバーを再有効化してすべてのツールを有効にし、**Disable All** はすべてを無効化します。

*改善*

- **より狭い信頼の提案**: 連結されたコマンド（`a && b` など）を承認したときに、権限確認がチェーン全体ではなく、**確認を引き起こした特定のコマンドに絞った信頼パターン**を提案するようになった
- **Steering インジケーターの再設計**: チャット内の Steering ファイルのインジケーターが、コンパスのアイコンとファイル種別に応じたラベルを持つ結果カードとして描画され、ツール呼び出しやフックの表示と揃った
- **検証優先のワークフローの UI**: Spec モードで、リアルタイムの進捗・受け入れ基準のチェック・要件の検証完了時の整合性バッジを表示するストリーミングの検証カードが出るようになった
- **ターミナルの引用符からの復旧**: シェルの引用符の継続による停止（`dquote>`・`bquote>` など）を自動検知し、5秒後に `Ctrl+C` を送って復旧する。エージェントがコマンドに閉じていない引用符を残したときの、よくある停止の原因が解消された

*修正*

- 会話の途中でモデルを切り替えてもグローバルの既定が変わらなくなった（新しいモデルはそのセッションに留まり、新規セッションは設定した設定から始まる）
- Windows でのターミナルの固まり
- 複数のセッションを開いているときにコマンドの出力が誤ったセッションに表示されることがある問題
- 完了した応答の末尾に余分な Markdown の文字が現れる問題
- チェックポイントに巻き戻したときにエージェントの設定が正しく復元されるように
- 保存したセッションを開き直したときにサブタスクのラベルが誤る、または統合される問題
- ドロップダウンを開いたときにタイトルバーのボタンの上にツールチップが現れる問題
- エンタープライズのファイアウォールの背後でモデル一覧の読み込みが失敗する問題
