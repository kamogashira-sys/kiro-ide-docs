# 0.x から 1.0 への移行ガイド

**0.x から 1.0 に上げると、フックとセッションが「移行するまで動かない」状態になります。その対処をまとめます。**

- **一次情報**: [What's new in IDE 1.0](https://kiro.dev/docs/ide/whats-new-v1/)
- **1.0 のリリース日**: 2026-06-25
- **本ガイドの対象**: 0.x（0.1〜0.12）から 1.0 系に更新した方

> **急いでいる方へ**: **§1 の対応が必要な2点**（フックとセッション）だけ先に読んでください。
> どちらも**移行しないと動きません**が、**期限はありません**。

---

## 1. 更新後にやること（一覧）

公式の「At a glance」に沿った一覧です。**「対応」列が空でない3項目**が作業を伴います。

| 領域 | 何が新しいか | **対応** |
|------|-----------|---------|
| **Permissions** | capability ベースのモデルで、エージェントができることを制御できる | **権限設定を見直す** |
| **Custom agents** | Markdown 形式のエージェントプロファイル（タグベースのツール・インライン MCP） | `.kiro/agents/` にエージェントを作る（任意） |
| **Agent Focus Mode** | エージェント中心のレイアウト・並列セッション（**実験的**） | 右上のトグルでオプトイン（任意） |
| **Dockable chat** | チャットセッションを全幅のエディタタブで開ける | チャットタブを右クリック → **Open in Editor**（任意） |
| **Export sessions** | 会話を可搬な zip として保存できる | チャットタブを右クリック → **Export Chat**（任意） |
| **セッションの始め方** | **Vibe / Spec の二択ピッカーが廃止**され、会話モードで始めてから必要に応じてワークフローを呼ぶ形になった | **対応不要**（§6 で違いを説明） |
| **インラインチャット** | **`Cmd+I` のインラインチャットが廃止**され、Ask Kiro ワークフローに置き換わった | **対応不要**（§6.1 で代替手段を説明） |
| ⚠️ **Hooks** | **構造化された v1 JSON 形式**＋自然言語での作成 | **既存のフックをパネルから移行する** |
| ⚠️ **Sessions** | 性能向上のための新しい保存形式 | **セッションを個別に、または開くことで移行する** |

> **公式の注記**: 最新の 1.0.x を入れるには [kiro.dev/downloads](https://kiro.dev/downloads/) から
> 直接ダウンロードしてください。**自動更新は段階的に展開中**です（[03_deployment/01_installation.md](../03_deployment/01_installation.md#5-更新)）。

## 2. ⚠️ フックの移行（必須）

### 2.1 何が変わったか

| | 0.x | **1.0** |
|-|-----|--------|
| ファイル形式 | **`.hook` ファイル** | **v1 JSON**（`.kiro/hooks/*.json`） |
| manual トリガ | **あり** | **廃止**（manual ステアリングファイルに置換） |

> ⚠️ **レガシーフック（0.x 由来）は、移行するまで実行されません。**
> Agent Hooks パネルに**アップグレードのバッジ付き**で表示されます。

### 2.2 移行手順

| 順 | 操作 |
|----|------|
| 1 | Kiro パネルの **Agent Hooks** セクションを開く |
| 2 | 未移行のフックには**アップグレードアイコンのバッジ**が付いている |
| 3 | **バッジをクリックする**（v1 形式に変換される） |
| 4 | **移行したフックは即座に有効になる** |

**元のレガシーファイルはディスク上に残りますが、もう読み込まれません。**

### 2.3 1.0.52 以降は自動移行される

**1.0.52（2026-07-02）で自動移行が入りました。**

| 項目 | 内容 |
|------|------|
| 契機 | **レガシーフックが有効化されたときに v1 JSON 形式へ移行される** |
| 状態表示 | ツリービューに表示される |
| **注意** | **互換性のないシェルコマンドはスキップされる** |

**スキップされたコマンドがある場合は手で書き直す必要があります。** 移行後にフックが期待通り動くか確認してください。

詳細は [01_changelog.md](01_changelog.md#v1-0-52) を参照してください。

### 2.4 manual フックはステアリングファイルになる

**manual トリガ（0.x の `Manual`）は manual ステアリングファイルに置き換わりました。**

| | 0.x | **1.0** |
|-|-----|--------|
| 実体 | manual トリガのフック | **`.kiro/steering/` の Markdown ファイル**（`inclusion: manual`） |
| 呼び出し方 | Agent Hooks パネルの再生ボタン | **`/<ファイル名>` スラッシュコマンド** |

**0.x で manual フックを持っていた場合、それらはステアリングファイルに移行されます。**

形式と機能は [01_features/06_steering.md](../01_features/06_steering.md#53-manual手動で含める) を参照してください。

### 2.5 1.0 でのフックの作り方

**UI の作成フローが変わりました。** Agent Hooks パネルの **`+`** を押すと2つの選択肢が出ます。

| 選択肢 | 内容 |
|-------|------|
| **Ask Kiro to create a hook** | **自然言語で説明**してフックを作ってもらう |
| **Manually create a steering file** | `.kiro/steering/` に Markdown ファイルを作り、**`/<ファイル名>` スラッシュコマンド**として呼び出す |

> **「手でフックを作る」選択肢がステアリングファイルの作成になっている**点に注意してください。
> v1 JSON を手で書きたい場合は、`.kiro/hooks/*.json` を直接編集します（[01_features/05_hooks.md](../01_features/05_hooks.md#41-json-ファイルを直接書く)）。

### 2.6 トリガー名も変わっている

**0.x 時代のトリガー名と v1 JSON の値は異なります。**

| 0.x の表示名（`hooks/types` ページ） | v1 JSON の値 |
|-------------------------------|------------|
| Prompt Submit | `UserPromptSubmit` |
| Agent Stop | `Stop` |
| Pre Tool Use | `PreToolUse` |
| Post Tool Use | `PostToolUse` |
| File Create | `PostFileCreate` |
| File Save | `PostFileSave` |
| File Delete | `PostFileDelete` |
| Pre Task Execution | `PreTaskExec` |
| Post Task Execution | `PostTaskExec` |
| **Manual Trigger** | **廃止**（§2.4） |
| （なし） | `SessionStart`（**1.0 で追加**） |

> ⚠️ **公式ドキュメントの [Hook types](https://kiro.dev/docs/hooks/types/) ページは更新日が 2026-02-18（1.0 より前）**で、
> **0.x 時代のトリガー名が載ったまま**です。v1 JSON を書くときは
> [Hooks](https://kiro.dev/docs/hooks/) ページの「Trigger reference」（更新日 2026-07-09）を参照してください。
> 本サイトの一覧は [01_features/05_hooks.md](../01_features/05_hooks.md#2-トリガーの一覧10種) にあります。

### 2.7 ファイル系トリガーの挙動が変わった（1.0.116）

**1.0.116（2026-07-09）以降、ファイル系のフックは「エージェントによる書き込み・作成・削除」でも発火します。** それ以前は手動保存が主な契機でした。

**format-on-save や review-on-create のフックが、エージェント起点の変更にも自動的に効くようになります。** 意図しない頻度で走る場合は `matcher` で絞ってください。

## 3. ⚠️ セッションの移行（必須）

### 3.1 何が変わったか

**1.0 は新しいセッション保存形式を使います。**

> ⚠️ **0.x のセッションは、移行するまでセッション一覧に現れません。**
> 移行済みのセッションが1つもない場合、チャットパネルはセッション一覧を開いて注意が必要なものを示します。

### 3.2 移行手順（2通り）

| 方法 | 操作 |
|------|------|
| **Migrate ボタンを押す** | 未移行のセッションには一覧に **Migrate** ボタンが表示される |
| **セッションを開く** | **未移行のセッションを選ぶと自動的に移行される** |

> **期限はありません。** 未移行のセッションはローカルに保存されたまま残り、必要になったときに移行できます。

### 3.3 うまく移行できないとき

セッション一覧で**右クリック**すると追加の選択肢が出ます。

| 操作 | 内容 |
|------|------|
| **Force Re-migrate** | **移行をゼロからやり直す**（最初の試行が不完全な結果になった場合に有効） |
| **Show Migration Logs** | 移行ログを開いて問題を診断する |

### 3.4 1.0.52 での改善

**1.0.52（2026-07-02）でセッション移行が改善されました。**

| 項目 | 内容 |
|------|------|
| タイミング | **利用者が起点となる操作**に変わった（自分のタイミングで移行できる） |
| **チェックポイント** | **ファイルのチェックポイントが保持される**ため、移行後のセッションでも取り消しが機能する |

## 4. Permissions（権限設定の見直し）

### 4.1 1.0 で初めて起きること

公式の説明:

- **1.0 を初めて使うとき、エージェントがファイルを書く・コマンドを実行する・MCP ツールを呼ぶときに同意プロンプトが出ます**
- 判断は「always allow」「always deny」のルールとして保存でき、**ワークスペース単位または全ワークスペース**にスコープできます
- **設定なしの状態では、エージェントはワークスペースのファイルを読み、読み取り専用の git コマンドを実行できます** — それ以外はすべて確認されます

**つまり、更新直後は確認プロンプトが増えます。** これは想定された挙動で、作業しながら承認していくとポリシーが育ちます。

### 4.2 やるべきこと

| # | 内容 |
|---|------|
| 1 | **最初の数回は同意プロンプトが出ることを想定しておく** |
| 2 | 定着したパターンは **Always allow** で保存する（スコープは **This workspace** から始めるのが安全） |
| 3 | 機密情報の読み取りは `deny` ルールで明示的に遮断する |
| 4 | **「信頼するコマンド」（Trusted Commands）の設定も併せて見直す**（権限とは別の仕組みで、前方一致で構造を解析しません） |

使い方は [01_features/03_permissions.md](../01_features/03_permissions.md)、書式の一覧は [04_reference/03_permissions.md](../04_reference/03_permissions.md) を参照してください。

### 4.3 1.0.52 での関連改善

| 改善 | 内容 |
|------|------|
| **プロジェクト外のファイルアクセスの同意** | ワークスペース外のファイルを読み書きする前に確認するようになった |
| **権限設定のパスピッカー** | **広範囲を一括拒否するルールを誤って作ることを防げる** |
| 権限カードのツール名表示 | 権限確認のヘッダーにツール名が表示される |

## 5. 任意で使える新機能（4つ）

移行作業は不要ですが、1.0 で使えるようになったものです。

### 5.1 Custom agents

**目的別のエージェントを Markdown ファイルで作れます。** タグ（`read`・`write`・`shell`・`web`）でツールを宣言し、MCP サーバと権限ルールをインラインに埋め込み、バージョン管理で共有できます。

| 特徴 | 内容 |
|------|------|
| **タグベースのツール** | 個別のツールを列挙せず、タグで能力を宣言する |
| **インライン MCP** | MCP サーバ設定をエージェントプロファイルに同梱する |
| **インライン権限** | 別の権限ファイルなしにエージェントのできることを絞る |
| **エージェントセレクタ** | **会話履歴を失わずにセッション中に切り替えられる** |

置き場所は `.kiro/agents/` です。詳細は [01_features/07_custom-agents.md](../01_features/07_custom-agents.md)。

### 5.2 Agent Focus Mode（実験的）

**エージェントとの会話を中心に据えたレイアウト**です。右上のボタンでいつでも切り替えられます。

> ⚠️ **実験的機能です。** 公式が「インターフェースと挙動は将来のリリースで変わる可能性がある」と警告しています。

詳細は [01_features/09_agent-focus-mode.md](../01_features/09_agent-focus-mode.md)。

### 5.3 Dockable chat

チャットタブを右クリック → **Open in Editor** で、**全幅のエディタタブ**として開けます。分割・ドラッグ・マルチモニタに対応します。

**パネルとエディタタブのどちらから送っても同じセッションに届きます。** 詳細は [01_features/02_chat.md](../01_features/02_chat.md#11-dockable-chatチャットをエディタタブで開く)。

### 5.4 Export sessions

チャットタブを右クリック → **Export Chat** で、会話を zip として保存できます。

**zip の中身**: セッション ID のディレクトリに `session.json`（メタデータ）と `messages.jsonl`（会話全体・改行区切り JSON）、サブエージェントの実行があれば `sub-executions/*.jsonl`。

**書き出しは読み取り専用**です（読み込み直せません）。詳細は [01_features/02_chat.md](../01_features/02_chat.md#102-zip-で書き出すexport-chat)。

## 6. セッションの始め方が変わった（対応不要）

**対応は不要ですが、0.x に慣れた方は操作が変わったことを知っておく必要があります。**

0.x では新しいチャットを始めるとき、**モードピッカー**で2つのセッション種別から選んでいました。

| 0.x のモード | 内容 |
|------------|------|
| **Vibe モード** | 自由形式の会話的なコーディング。質問・編集・探索的な作業を構造なしで扱う |
| **Spec モード** | 構造化された開発。要件・設計・タスクの各フェーズを承認ゲート付きで進む |

**1.0 でこの二択ピッカーは廃止されました。** 代わりに次のようになっています。

| 1.0 での仕組み | 内容 |
|--------------|------|
| **デフォルトエージェント** | すべてのセッションは汎用の会話エージェントで始まる（**旧 Vibe モード相当**） |
| **ワークフローセレクタ** | 新しいセッションを開くと「Let's build」画面が組み込みワークフロー（**Spec・Plan・Bug Fix・Quick Spec**）を提示する。選ぶとそのセッションのエージェントが切り替わる |
| **セッション中の切り替え** | チャット入力欄のエージェントピッカーからいつでも切り替えられる。**開始時に決める必要がない** |
| **カスタムエージェント** | モードを切り替える代わりに、用途ごとの専用エージェントを作れる |

**つまり「このセッションは vibe か spec か」を先に決める必要がなくなりました。** 会話で始めて、
必要になった時点で構造化ワークフローを同じセッション内から呼び出せます。

現行の操作方法は [01_features/02_chat.md](../01_features/02_chat.md#3-セッションの始め方10-で二択ピッカーが廃止) を参照してください。

### 6.1 インラインチャット（`Cmd+I`）も廃止された

**公式は「Inline chat is retired in IDE 1.0」と明記しています**（changelog 1.0 の
「Inline Chat replaced by Ask Kiro workflow」項目）。**代替手段は次の3つです。**

| 代替手段 | 操作 |
|---------|------|
| 選択したコードを現在のチャットに渡す | **`Cmd+L`** / `Ctrl+L` |
| 選択したコードで新しいセッションを始める | **`Cmd+Shift+L`** / `Ctrl+Shift+L` |
| 右クリックメニュー | **Kiro > Ask Kiro**（**Fix Grammar / Spelling**・**Write Comments for this Code**・**Optimize this Code** のクイックアクションもここから） |

**廃止の理由**（公式）: 選択範囲をチャットに渡せば、**エージェントはすでにプロジェクトの文脈・履歴・
すべてのツールを持っている**状態で作業できるためです。

> ⚠️ **Supervised モードのハンクレビュー内の「Chat inline」は別物で、現行機能として残っています**
> （[01_features/04_autopilot-supervised.md](../01_features/04_autopilot-supervised.md#5-supervised-でのレビュー6段階の粒度)）。

## 7. 0.x に戻す場合

不具合が出た場合は 0.x に戻せます。手順は [03_deployment/01_installation.md](../03_deployment/01_installation.md#6-旧版に戻すダウングレード) を参照してください。

> **設定・拡張機能・サインイン状態は再インストールをまたいで保持されます。**
>
> ⚠️ **ただし、1.0 で移行したセッションが 0.x で読めるかについて公式の記述はありません（未確認）。**
> フックについても、v1 JSON に移行したものが 0.x で動くかは公式に記述がありません（**未確認**）。
> **元のレガシーファイルはディスクに残っている**ため、0.x に戻せば以前のフックは読まれる可能性がありますが、
> これも公式に確認できていません。
