# セキュリティとデータの扱い

**エージェントに何がどこまで許されるか・ネットワークで許可すべき URL・データがどこに保存されるかを扱います。**

> **本ページの範囲**: これらの公式ページは **IDE/CLI 共有**ですが、内容は URL ツリーごとに描画が変わります。
> 本ページの記述は **IDE ツリー（`/docs/privacy-and-security/...`）の表示内容**に基づいています。

## 1. まず押さえること: Supervised モードはセキュリティ機構ではない

Kiro には **Autopilot** と **Supervised** の2つのモードがあります。公式が警告として明記している点:

> **Supervised モードはコードレビューのワークフローであり、セキュリティ制御ではありません。**
> エージェントが生成した変更をレビュー・承認するためのものです。**サンドボックス・分離境界・アクセス制御機構としては機能しません。**

**両モードでエージェントの権限は同一です。** 違いは「レビューのタイミング」だけです。

| 能力 | Autopilot | Supervised |
|------|-----------|------------|
| ファイルを読む | できる | できる |
| ファイルをディスクに書く | できる | **できる** |
| コマンドを実行する | できる（信頼するコマンドのポリシーに従う） | できる（同じ） |
| 変更適用前のレビュー | **なし**（即時適用） | **あり**（差分を見て承認/却下） |
| 巻き戻し | 手動（**Revert all changes** またはチェックポイント） | 却下時に自動。手動も可 |
| 保護されたパスへの書き込みを承認なしに防ぐ | **する** | する |

**エージェントのアクセス範囲を絞るには**、保護されたパス・信頼するコマンド・ワークスペースの分離・資格情報のスコープ設定を使います（§2・§3）。capability ベースの権限設定は [04_reference/03_permissions.md](../04_reference/03_permissions.md) にまとめています。

### 1.1 Supervised モードの動き

**どちらのモードでも、エージェントはツール実行中にファイル変更をディスクへ書きます。** Supervised モードではその書き込みにレビュー用のタグが付き、エージェントのターンが終わった時点で承認/却下を求められます。却下するとファイルはターン開始前の状態に戻ります。

**必ずレビュー対象になるファイル操作（7種）**:

| 操作 | 内容 |
|------|------|
| ファイル作成・上書き | 新規作成、内容の置き換え |
| テキスト置換 | ファイル内の特定のテキストを置換 |
| 内容の追記 | ファイル末尾への追加 |
| ファイル削除 | ワークスペースからの削除 |
| コード編集 | ファイル内のコードの変更 |
| シンボルのリネーム | 変数・関数・クラスを横断的にリネーム |
| ファイルの移動 | 移動と参照の更新 |

**このレビューは Kiro のワークフローに組み込まれており、AI モデルがスキップすることはできません。**

**承認の粒度**: Supervised では**ハンク単位**で個別に承認/却下できます。連続する同一ファイルへの編集はまとめられることがあります（中断を減らすため）。

### 1.2 Supervised モードの限界（公式明記）

- レビュー対象は **Kiro のファイル編集操作を通じた変更のみ**
- 信頼するコマンド一覧に入れたシェルコマンドは**別の承認経路**に従う
- **エージェントがどのファイルを読めるか・どんなコマンドを提案できるか・どんなネットワークアクセスを持つかは制限しない**

### 1.3 モードの選び方

| 状況 | 推奨 |
|------|------|
| 作業範囲を信頼していて中断されたくない | **Autopilot** |
| 変更を1つずつ確認したい | **Supervised** |
| 公式が挙げる Supervised 向きの場面 | 不慣れなコードベース・重要な経路の変更・エージェント支援に慣れていない新メンバーのオンボーディング |

どちらのモードでも、**Chat** モジュールの **View all changes** で変更を確認でき、**Revert all changes** またはチェックポイントで元に戻せます。

## 2. 信頼するコマンド（Trusted commands）

**既定ではすべてのコマンドが承認を求めます。** 設定で **Kiro Agent: Trusted Commands** を検索すると、自動的に信頼するコマンドの一覧を作れます。

**マッチ方式は単純な前方一致（文字列の先頭比較）です。**

| 方式 | 例 |
|------|-----|
| 完全一致 | `npm install` |
| ワイルドカード | `npm *`（すべての npm コマンドを信頼する） |
| 全許可 | `*` 単独（**すべてのコマンドを信頼する。極めて慎重に**） |

公式の警告:

> システムはコマンド全体を1つの文字列として扱い、信頼するパターンで始まるかだけを見ます。
> **コマンドの構造・連結・特殊文字を解析しません。** 慎重にパターンを設定する責任はすべて利用者にあります。

> **具体的に何が危ないか**: `npm *` を信頼すると、前方一致なので `npm install && rm -rf /` のような
> 連結コマンドも「`npm ` で始まる」と判定されます。構造を見ていないためです。
> **信頼する一覧は最小限にし、広いワイルドカードは避けてください**（公式も繰り返し推奨しています）。

## 3. 保護されたパス（Protected paths）

Kiro は特定のパスへの書き込みに明示的な承認を求めます。**Autopilot と Supervised の両モードで有効**です。エージェントが該当パターンに一致するファイルを作成・変更しようとすると確認プロンプトが出て、承認するまで変更は適用されません。断ると、エージェントはその書き込みをスキップして残りの作業を続けます。

| パターン | マッチ方式 | 対象 |
|---------|----------|------|
| `.vscode/` | パスに含む | VS Code のワークスペース設定 |
| `vscode~` | パスに含む | VS Code のバックアップ・復旧ファイル |
| `.git/` | パスに含む | `.git` ディレクトリ内のファイル |
| `git~` | パスに含む | Git のロック・バックアップファイル |
| `.code-workspace` | パスに含む | マルチルートワークスペースファイル |
| `.git` | ベース名の完全一致 | `.git` ディレクトリまたはサブモジュールファイルそのもの |
| `mcp.json` | ベース名の完全一致 | MCP サーバ設定 |
| `.kiroignore` | ベース名の完全一致 | Kiro の無視ルール |

**マッチ方式の違い**:

| 方式 | 意味 |
|------|------|
| **パスに含む** | パス中のどこかにパターンが現れれば一致。`.vscode/` は `.vscode/settings.json` にも `.vscode/extensions.json` にも一致する |
| **ベース名の完全一致** | ファイル名（パスの最後の部分）がパターンと完全に等しいときだけ一致。`mcp.json` は `project/mcp.json` に一致するが **`mcp.json.bak` には一致しない** |

## 4. ファイアウォールで許可する URL

ファイアウォール・プロキシ・データ境界がある環境では、Kiro が backend に到達できるよう URL を許可リストに入れる必要があります。

### 4.1 通信の2系統

| 系統 | 内容 | プロキシ設定 |
|------|------|------------|
| **IDE の通信** | チャット・補完・テレメトリ・更新・拡張機能 | **IDE のプロキシ設定に従う** |
| **ブラウザの通信** | サインイン（既定のブラウザが開く） | **OS のネットワークスタックを使い IDE のプロキシ設定を通らない** |

**ファイアウォールでは両方をネットワークレベルで許可する必要があります。**

### 4.2 全製品で必須の URL

| URL | 用途 |
|-----|------|
| `app.kiro.dev` | サインインポータル |
| `assets.app.kiro.dev` | アプリケーションのアセット |

### 4.3 すべての Kiro インストールで必要な URL（IDE）

| URL | 用途 |
|-----|------|
| `prod.us-east-1.auth.desktop.kiro.dev` | トークンの交換・更新・ログアウト |
| `prod.us-east-1.telemetry.desktop.kiro.dev` | テレメトリ |
| `prod.download.desktop.kiro.dev` | **自動更新**・Powers レジストリ・アイコン |
| `q.us-east-1.amazonaws.com` | Kiro サービス（US East） |
| `q.eu-central-1.amazonaws.com` | Kiro サービス（Europe） |
| `runtime.us-east-1.kiro.dev` | Kiro サービス（US East） |
| `runtime.eu-central-1.kiro.dev` | Kiro サービス（Europe） |
| `management.us-east-1.kiro.dev` | 設定・アクセス管理（US East） |
| `management.eu-central-1.kiro.dev` | 設定・アクセス管理（Europe） |
| `telemetry.us-east-1.kiro.dev` | テレメトリ（US East） |
| `telemetry.eu-central-1.kiro.dev` | テレメトリ（Europe） |

> **`prod.download.desktop.kiro.dev` は更新の入口です。** [04_enterprise.md](04_enterprise.md) の
> バージョン固定を確実にするには、この URL を**遮断**して自社の更新エンドポイントのみ許可します。

### 4.4 認証方式ごとに追加で必要な URL

**ソーシャルサインイン（GitHub・Google・AWS Builder ID）**:

| URL | 用途 |
|-----|------|
| `cognito-identity.us-east-1.amazonaws.com` | ソーシャルサインインのフェデレーテッド ID |

**IAM Identity Center**（`<...>` の部分は環境ごとの値に置き換え）:

| URL | 用途 |
|-----|------|
| `<region>.signin.aws` | AWS サインイン |
| `<sso-region>.signin.aws.amazon.com` | AWS サインイン（別形式） |
| `<idc-directory-id-or-alias>.awsapps.com` | IAM Identity Center ポータル |
| `portal.sso.<sso-region>.amazonaws.com` | SSO ポータル |
| `assets.sso-portal.<sso-region>.amazonaws.com` | SSO ポータルのアセット |
| `oidc.<sso-region>.amazonaws.com` | OIDC のトークン交換 |

**外部 ID プロバイダ**:

| ID プロバイダ | 許可するドメイン |
|-------------|--------------|
| Microsoft Entra ID | `login.microsoftonline.com` |
| Okta | `<your-org>.okta.com` |

**AWS GovCloud (US)** を使う場合は、上の Core URLs にある商用の Kiro サービスエンドポイントの**代わりに** FIPS 準拠のエンドポイントを許可します。

- `q-fips.us-gov-east-1.amazonaws.com`
- `q-fips.us-gov-west-1.amazonaws.com`

> **GovCloud リージョンは `kiro.dev` の DNS 名に対応していません。** `q-fips.*.amazonaws.com` のみが利用できます。

**サブスクリプション管理**（Google・GitHub・AWS Builder ID でサインインする場合。Stripe を使用）:

| URL | 用途 |
|-----|------|
| `billing.stripe.com` | 有料プランの請求ポータル |
| `checkout.stripe.com` | プランのアップグレード |

> エンタープライズで IAM Identity Center を使う場合、これらの Stripe ドメインは不要です。

### 4.5 機能を使う場合だけ必要な URL

| URL | 機能 | 用途 |
|-----|------|------|
| `open-vsx.org` | 拡張機能 | 検索とメタデータ |
| `openvsx.eclipsecontent.org` | 拡張機能 | アイコンと VSIX のダウンロード |
| `github.com` | Powers / MCP | リポジトリのクローン |
| `raw.githubusercontent.com` | Powers / MCP | 設定ファイルと readme の画像 |

### 4.6 プロキシの設定

Kiro は IDE の全通信で標準のプロキシ環境変数を尊重します。

- `HTTP_PROXY`
- `HTTPS_PROXY`
- `NO_PROXY`

Kiro 内の **Settings > Proxy** でも設定できます。

> **サインインはプロキシ設定を回避します。** サインイン時、Kiro は既定のブラウザで `app.kiro.dev` を開きます。
> この通信は OS のネットワークスタックを使うため、IDE のプロキシ設定に関わらず
> **IAM Identity Center の URL と `app.kiro.dev` をネットワークレベルで許可する**必要があります。

> **ワイルドカードでの簡略化について**: 公式ページには `*.kiro.dev` などのワイルドカード一覧表が
> ありますが、これは **Kiro Web 向けの表示にのみ現れます**（IDE ツリーの表示には節そのものが存在しません）。
> IDE 向けの本文には「Wildcard rules を参照」というリンクがありますが、**同じページ内に節がない**状態です。
> IDE 環境でワイルドカードを使う場合は、上記の個別 URL を基準に自組織で判断してください（公式の IDE 向け記述としては**未確認**）。

## 5. データはどこに保存され、どう扱われるか

### 5.1 保存されるもの

Kiro は質問・応答・コードなどの追加コンテキスト・リクエストのメタデータを保存します。プロンプトログや日次利用レポートを有効にした場合は、レポート発行とイベント記録に必要なデータも保存されます。

### 5.2 保存されるリージョン

| 利用者の種別 | コンテンツの保存先 |
|------------|----------------|
| **Free Tier・個人サブスクライバー** | **US East (N. Virginia) リージョン** |
| **エンタープライズ利用者** | **プロファイルを設定したリージョン**（サービス提供・維持のため。サービス改善には使われない） |

### 5.3 リージョン間推論（Cross-region inference）

Kiro は Amazon Bedrock を基盤とし、**リージョン間推論**でトラフィックを分散して推論性能と信頼性を高めています。

**リージョン間推論はデータの保存先を変えません。** 処理が行われるのは、データが保存されている地理的範囲内の別リージョンです。

| 地理的範囲 | 推論が行われうるリージョン |
|-----------|----------------------|
| **United States** | US East (N. Virginia) `us-east-1` / US West (Oregon) `us-west-2` / US East (Ohio) `us-east-2` / AWS GovCloud (US-East) / AWS GovCloud (US-West) |
| **Europe** | Europe (Frankfurt) `eu-central-1` / Europe (Ireland) `eu-west-1` / Europe (Paris) `eu-west-3` / Europe (Stockholm) `eu-north-1` / Europe (Milan) `eu-south-1` / Europe (Spain) `eu-south-2` |

> **実験的機能は例外です（重要）**: 実験的タグの付いたモデル・機能では**グローバルなリージョン間推論**が使われ、
> **Kiro プロファイルのリージョン外を含む世界中の商用 AWS リージョンで処理される可能性があります**。
> データの保存先は変わりませんが、処理場所に制約がある組織では実験的機能の扱いを検討する必要があります。

### 5.4 暗号化

| 区分 | 内容 |
|------|------|
| **転送中** | 利用者と Kiro の間、および Kiro と下流の依存先の間のすべての通信を **TLS 1.2 以上**で保護 |
| **保管時** | AWS KMS の **AWS 所有キー**で暗号化（利用者側の操作は不要） |
| **保管時（エンタープライズ）** | 管理者が**カスタマー管理キー**を作成して使える。**対称キーのみ対応**。作成後、Kiro コンソールでキーを指定する |

### 5.5 サービス改善への利用とオプトアウト

| 利用者の種別 | サービス改善への利用 |
|------------|-----------------|
| **Free Tier・個人サブスクライバー** | **利用される場合がある**（質問・入力・生成された応答とコード。より良い回答の提供・運用上の問題の修正・デバッグ・**モデルの学習**などに使われる） |
| **エンタープライズ利用者** | **利用されない**（テレメトリとコンテンツ収集から自動的にオプトアウトされる） |
| Amazon Q Developer Pro サブスクリプション経由 | 利用されない |

**IDE でオプトアウトする手順**:

| 順 | 操作 |
|----|------|
| 1 | Kiro で **Settings** を開く |
| 2 | **User** サブタブに切り替える |
| 3 | **Application** → **Telemetry and Content** を選ぶ |
| 4 | テレメトリを止める: **Data Sharing and Prompt Logging: Usage Analytics And Performance Metrics** のチェックを外す<br>コンテンツ収集を止める: **Data Sharing and Prompt Logging: Content Collection for Service Improvement** のチェックを外す |

> **Free Tier では、サービス改善のオプトアウトをしても不正利用検知のための入力保存は止まりません**（公式明記）。
> Free Tier の入力は不正利用検知の目的で**最大60日間**保存される場合があります。
> OpenAI の GPT モデルでは、分類器がフラグを立てたトラフィックが**最大30日間**保持されます
> （保持先は推論が行われたリージョン）。

**収集されるテレメトリの種類**:

| 種別 | 内容 |
|------|------|
| **利用データ** | Kiro のバージョン・OS（Windows / Linux / macOS）・**匿名のマシン ID** |
| **性能メトリクス** | 機能ごとのリクエスト数・エラー・レイテンシ（ログイン / タブ補完 / コード生成 / Steering / Hooks / Spec 生成 / ツール / MCP） |

## 6. コードリファレンス（公開コードとの類似の通知）

Kiro はオープンソースプロジェクトからも学習しているため、提案が公開コードに似ることがあります。**コードリファレンス**は、その提案の生成に使われた出典の情報です。

| 項目 | 内容 |
|------|------|
| **既定** | **無効**（disabled by default） |
| 有効化 | **Settings** → **User** サブタブ → **Kiro** → **Code References: Reference Tracker** の「Allow Kiro to generate code with references」をチェック |
| ログの参照 | ステータスバーの **Output** タブ → ドロップダウンで **code-references** を選ぶ（有効かつリファレンス付きコードが生成されたときだけ現れる） |
| エンタープライズ | **管理者が全利用者に対してオプトアウトできる**。この設定は管理者が制御し、**利用者側では上書きできない** |

## 7. 公式が挙げるベストプラクティス

GitHub や Google の認証で Kiro を使う場合、エージェントは利用者のローカル環境で動作し、次のものにアクセスしうることに注意が必要です。

- ローカルのファイルとリポジトリ
- 環境変数
- **環境に保存された AWS の資格情報**
- 機密情報を含むその他の設定ファイル

公式の推奨（4項目）:

| # | 項目 | 内容 |
|---|------|------|
| 1 | **ワークスペースの分離** | 機密プロジェクトは別ワークスペースに置く／`.gitignore` で機密ファイルへのアクセスを防ぐ／IDE のワークスペーストラスト機能を検討する |
| 2 | **クリーンな環境を使う** | Kiro 専用のユーザーアカウントやコンテナ環境の作成を検討する／現在のプロジェクトに必要なリポジトリとリソースだけにアクセスを限定する |
| 3 | **AWS 資格情報を慎重に扱う** | 適切な権限を持つ一時的な資格情報を使う／名前付きプロファイルで Kiro のアクセスを分離する／機密作業では**必要ないときは環境から AWS 資格情報を外す** |
| 4 | **リポジトリのアクセス制御** | GitHub 認証時に Kiro がアクセスできるリポジトリを確認する／可能ならリポジトリ固有のアクセストークンを使う／権限を定期的に監査する |

> **エージェントに見せないファイルを指定するには** `.kiroignore` を使います（[04_reference/01_kiro-directory.md](../04_reference/01_kiro-directory.md)）。
> `.gitignore` と同じ書き方のパターンでアクセスを制御できます。

### 7.1 リモート拡張機能の注意

公式の警告:

> リモート拡張機能を使うとローカルマシンとリモートマシンの間に接続が開きます。
> **信頼できる相手が所有する、安全なリモートマシンにのみ接続してください。**
> 侵害されたリモートは、その接続を使ってローカルマシン上でコードを実行しうります。

サードパーティ拡張機能（リモート拡張機能を含む）は Kiro が開発・保守・管理しているものではなく、安定性・互換性・継続的なサポートは保証されません。

## 8. URL の取得（`web_fetch`）について

チャットで URL を貼ると、その内容を取得してコンテキストとして使えます。公式は「**取得する URL の内容について、およびその利用が第三者の規約や法令に準拠していることについては利用者に責任がある**」と明記しています。

Web ツールは組織側で無効化できます（[04_enterprise.md](04_enterprise.md) §4）。
