# Cloud Sessions（クラウドサンドボックスで動くセッション）

**ローカルマシンではなく管理されたクラウドサンドボックスでエージェントを実行し、IDE・CLI・Web・Mobile のどこからでも同じセッションを継続できる仕組みです。1.0.293 でプレビュー導入されました。**

- **一次情報**: [Cloud sessions](https://kiro.dev/docs/cloud-sessions/)（公式ページ更新日: 2026-08-14）
- **導入バージョン**: **1.0.293**（2026-08-11）
- **位置づけ**: **プレビュー機能**
- **Kiro CLI 版の対応ページ**: 共通仕様。CLI からの作成・接続には **Kiro CLI 2.17 以降**が必要（[`docs/cloud-sessions/`](https://kiro.dev/docs/cloud-sessions/) が正。CLI 固有の個別ページはない）

> ⚠️ **プレビュー機能です。** IDE からの作成・接続には **Kiro IDE 1.0.293 以降**が必要です。

> **これは何か**: **セッションを実行する場所を、自分のマシンからクラウドのサンドボックスに移します。** セッションは特定のアプリではなく Kiro アカウントに属します。
> ブラウザでセッションを始めて長いタスクを渡し、ノートパソコンを閉じても、後でスマートフォン・ターミナル・IDE から様子を確認できます。
> **接続の有無にかかわらず、サンドボックス内でエージェントは動作し続けます。**

---

## 1. Kiro Web・Mobile を支える実行環境

**Cloud Sessions は [Kiro Web](https://kiro.dev/docs/web/) と Mobile の背後にある実行環境そのものです。** IDE と CLI も同じセッションを作成・接続できます。すべてのサーフェスが同じプロトコルで同じエージェントハーネスと通信するため、Cloud Session は他の Kiro セッションと同じように振る舞います（同じ steering・同じ permissions・同じツール）。**唯一の違いは、作業が実行される場所です。**

---

## 2. 動作の仕組み

Cloud Session を作成すると、Kiro は分離されたサンドボックスを準備し、IDE・CLI でローカルに動くのと同じエージェントハーネスを起動します。

| 項目 | 内容 |
|------|------|
| リポジトリの取得 | リポジトリを紐づけると、**サーバー側で**接続済みのソースプロバイダ経由でクローンされる。**ローカルの作業コピーはアップロードされない** |
| 実行場所 | エージェントはサンドボックス内でファイルの読み取り・編集・ビルド・シェルコマンドの実行を行う |
| 結果の返却 | ソースプロバイダ経由（通常はプルリクエスト）または会話内で直接返される |

**セッション自体は、クライアントとは別の「クラウドセッションストア」に存在します:**

| 特性 | 内容 |
|------|------|
| **クライアントは着脱可能** | Web・Mobile・IDE・CLI はすべて同じセッションを映すビュー。クライアントの切断はエージェントを止めない。実行中のタスクは動き続ける |
| **状態はマシンをまたいで残る** | 会話履歴・紐づけたリポジトリ・サンドボックスのファイル状態はクラウドに保持される。どのサーフェスから再接続しても、トランスクリプトは中断箇所から再生される |
| **承認はユーザーを待つ** | 誰も接続していない間にエージェントが権限を必要とした場合、リクエストは保留され、次に接続したクライアントに提示される |

サンドボックス自体（ネットワークアクセス・環境変数・環境設定）の詳細は公式 [Sandbox](https://kiro.dev/docs/web/sandbox/) ドキュメントを参照してください。

## 3. 前提条件

| # | 条件 |
|---|------|
| 1 | 有料の Kiro サブスクリプション（Pro 以上） |
| 2 | リポジトリで作業する場合は、接続済みの GitHub または GitLab アカウント |
| 3 | **AWS IAM Identity Center 組織の場合**: 管理者が Kiro の設定先 AWS アカウントの **Settings > Kiro Settings** で **Cloud Sessions (Preview)** を有効化する必要がある。プレビュー期間中は **US East (N. Virginia) `us-east-1`** でのみ実行される |

## 4. IDE での使い方

**IDE では、Cloud Sessions は [Agent Focus Mode](09_agent-focus-mode.md) の中にあります。** IDE 右上から Agent Focus を開くと、セッションレールにローカルのプロジェクトと並んで **Cloud Sessions** セクション（**Preview** バッジ付き）が表示されます。このセクションは、アカウントで Cloud Sessions が利用可能な場合に現れます。

### 4.1 Cloud Session を開始する

| 順 | 操作 |
|----|------|
| 1 | Cloud Sessions セクションのヘッダーで **＋**（**New Cloud Session**）を選ぶ。これはドラフトを開くだけで、まだクラウドには何も作成されない |
| 2 | 任意で、コンポーザー下部の **Select repos** から接続済みのソースプロバイダのリポジトリを1つ以上紐づける。選んだリポジトリは削除可能なピルとして表示される |
| 3 | モデル・エージェントまたはワークフロー・自律レベルを選ぶ。Cloud Sessions では **Autopilot** と **Autonomous** が選べる（Autonomous を選ぶとモードとモデルの選択もエージェントに委ねられる） |
| 4 | 最初のプロンプトを入力して送信する。Kiro がサンドボックスを準備し、選んだリポジトリをクローンしてプロンプトを送る。セットアップ中はコンポーザーがロックされる |

セッション開始後、紐づけたリポジトリはチャット入力の下に表示され続けます。**リポジトリは作成時に選ぶ**ため、別のリポジトリで作業したい場合は新しい Cloud Session を開始します。

### 4.2 Cloud Session の管理

セッションのコンテキストメニューから:

| 操作 | 内容 |
|------|------|
| **Pin Session** | セクションの先頭に固定する |
| **Open in Kiro Web** | ブラウザで同じセッションを継続する |
| **Open with Kiro CLI** | ターミナルから接続する（**Kiro CLI 2.16.2 以降**が必要） |
| **Delete Session** | セッションとそのサンドボックスを完全に削除する |

### 4.3 ローカルセッションと違う点（重要）

セッションのファイルはワークスペースではなくサンドボックスにあるため、**ローカルファイルを操作する機能は Cloud Session では使えません**:

| 使えない機能 |
|------------|
| エディタでのファイル・差分表示 |
| チェックポイントと巻き戻し |
| `#File`・`#Folder`・`#Terminal`・`#Problems` のコンテキストピッカー |
| フック設定へのリンク |
| クリック可能な spec タスクのアクション |

プロンプトへの添付（画像・文書）は使えます（内容はセッションに送信されます）。**Cloud Session のリネームと Supervised モードはまだ利用できません。**

## 5. 実行される場所（ローカル vs サンドボックス）

| 項目 | ローカルマシン | クラウドサンドボックス |
|------|--------------|---------------------|
| プロンプトと添付ファイル | ここで作成 | セッションに送信される（添付の内容はアップロードされる） |
| リポジトリのコード | **アップロードされない** | ソースプロバイダ連携経由でサーバー側でクローン |
| エージェントのファイル読み書き | — | サンドボックス内で実行 |
| シェルコマンドとビルド | — | サンドボックス内で実行 |
| プロジェクト設定（リポジトリ内の `.kiro/`） | — | リポジトリのクローンとともに届く |
| 個人設定（`~/.kiro/`） | ローカルに留まる | **自動適用されない**（§6 参照） |

---

## 6. クラウドでの設定

設定は他の場所と同じ[スコープ](../04_reference/01_kiro-directory.md)に従いますが、次の点に注意してください。

| 種別 | 挙動 |
|------|------|
| **プロジェクト設定** | リポジトリ内の `.kiro/` にコミットされた steering・spec・カスタムエージェント・フック・MCP サーバは、サンドボックスがリポジトリをクローンするため**自動的に適用される** |
| **個人設定** | `~/.kiro/` ディレクトリは**自動適用されない**。個人の steering・カスタムエージェント・Skills・フックを Cloud Session に持ち込むには、Kiro Web の設定にある **Cloud configuration** から同期する |
| **サンドボックス環境** | インターネットアクセス・環境変数・セットアップコマンドは Sandbox ドキュメントで扱う |

---

## 7. サーフェス間の移動

**Cloud Session は1つのセッションであり、どのアプリで見るかが違うだけです。**

| 移動元 | 移動先 | 方法 |
|-------|-------|------|
| Web / Mobile | CLI | `kiro-cli --resume-id <session-id>` |
| IDE（Agent Focus） | Web | セッションメニューの **Open in Kiro Web** |
| IDE（Agent Focus） | CLI | セッションメニューの **Open with Kiro CLI** |
| CLI | Web | `app.kiro.dev` でセッションを開く |
| いずれか | Mobile | Mobile アプリのセッション一覧に表示される |

---

## 8. 現在のプレビューの制限事項

| # | 制限 |
|---|------|
| 1 | **リポジトリの組み合わせは固定**: セッション作成時に選ぶ（CLI では後から `/repo` でも追加できる）。別のリポジトリで作業するには新しいセッションを開始する |
| 2 | **ブランチの選択不可**: リポジトリ紐づけ時にブランチを選べない。セッション開始後にエージェントへチェックアウト・作成を依頼する |
| 3 | **Supervised モード不可**: Cloud Session は Autopilot または Autonomous でのみ動作し、変更ごとの承認はできない |
| 4 | **リネーム不可**: IDE・CLI からリネームできない |
| 5 | **サーフェスごとの機能差**: 各サーフェスで使えないコマンド・機能があり、プレビューの成熟に伴って縮小が見込まれる |
