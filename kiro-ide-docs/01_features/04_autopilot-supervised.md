# Autopilot と Supervised（2つの実行モード）

**エージェントの変更をいつレビューするかを決める2つのモードです。**

- **一次情報**: [Autopilot](https://kiro.dev/docs/chat/autopilot/)・[Privacy and security（Autopilot versus supervised mode）](https://kiro.dev/docs/privacy-and-security/#autopilot-versus-supervised-mode)

> ⚠️ **最初に押さえること**: **Supervised モードはセキュリティ機構ではありません**（公式が警告として明記）。
> **両モードでエージェントの権限は同一**で、違いは**レビューのタイミング**だけです。
> アクセス範囲を絞りたい場合は [03_permissions.md](03_permissions.md) の権限設定を使います。

---

## 1. 2つのモードの違い

| | **Autopilot（既定）** | **Supervised** |
|-|---------------------|---------------|
| 動き | **自律的に端から端まで**作業する | **ファイル編集を含む各ターンの後**に承認を求めて止まる |
| 変更の適用 | **即座に適用**（あとから確認する） | ディスクには書かれるが、**ターン終了時に承認/却下を求める** |
| 承認の粒度 | — | **ハンク単位**（ファイル単位・一括も可） |
| 巻き戻し | 手動（**Revert all changes** またはチェックポイント） | **却下時に自動**。手動も可 |

### 1.1 権限は同一（公式の比較表）

| 能力 | Autopilot | Supervised |
|------|-----------|------------|
| ファイルを読む | できる | できる |
| **ファイルをディスクに書く** | できる | **できる** |
| コマンドを実行する | できる（信頼するコマンドのポリシーに従う） | できる（同じ） |
| 変更適用前のレビュー | **なし** | **あり** |
| 保護されたパスへの書き込みを承認なしに防ぐ | する | する |

**Supervised でも、エージェントはツール実行中にファイルをディスクへ書きます。** その書き込みにレビュー用のタグが付き、ターン終了時に確認されるという仕組みです。却下するとターン開始前の状態に戻ります。

---

## 2. 切り替え方

**チャット画面の autopilot スイッチで、いつでも切り替えられます。** タスクに応じて適切な制御水準を選べます。

---

## 3. どちらを使うか（公式の指針）

| **Autopilot が向く** | **Supervised が向く** |
|-------------------|---------------------|
| ・Kiro の能力に慣れた**経験のある利用者**<br>・繰り返し作業・**よく定義されたタスク**<br>・速く進めたいプロジェクト<br>・**複数ファイルにまたがる**、あるいは何段階も必要なタスク | ・**Kiro に慣れていない新しい利用者**<br>・**重要な、あるいは機密性の高いコードベース**<br>・Kiro の問題への取り組み方を学ぶ<br>・**変更を1つずつ丁寧に確認したい**<br>・不慣れなコードや複雑なシステムを扱う |

公式は「タスクに対する慣れと必要性に応じていつでも切り替えてよい」としています。

---

## 4. Autopilot での制御手段（3つ）

自律的に動きますが、制御を失うわけではありません。

### 4.1 View All Changes（すべての変更を見る）

**Chat** モジュールの **View all changes** で、Kiro が加えたすべての変更を一覧できます。**差分ビュー**で追加・変更・削除が明確に表示されます。

### 4.2 Revert All Changes（すべて戻す）

**Revert** を選ぶと、ファイルがローカルの以前の状態に復元されます。Kiro の変更全体に対する「取り消し」です。

> **チェックポイントとの違い**: チェックポイントは**ファイルの変更とコンテキストの追加の両方**を戻します。
> Revert はファイルのみです（[02_chat.md](02_chat.md) §8）。

### 4.3 Interrupt Execution（実行を中断する）

実行の途中で中断して手動の制御に戻せます。**何かおかしいと気づいた時点でそれ以上の変更を止められます。**

---

## 5. Supervised でのレビュー（6段階の粒度）

**ファイル編集を含む各ターンの後に承認を求めます。** これは **vibe チャットでも spec チャットでも同じ**です。

| # | 機能 | 内容 |
|---|------|------|
| 1 | **変更のレビュー** | 何が変更されたかが、チャット内の**行数の増減表示（+x -y lines）**とともに示される |
| 2 | **ファイル単位のレビュー** | 複数ファイルが編集された場合、**ファイルごとに個別に**承認/却下できる |
| 3 | **ハンク単位のレビュー** | 変更が**ハンク**（関連する行の論理的なまとまり）として提示される。ハンクごとに独立して承認・却下・**インラインチャットで修正依頼**ができる |
| 4 | **ハンクごとの操作** | **Accept**（このハンクを適用）／**Reject**（このハンクだけ破棄）／**Chat inline**（このハンクについて会話を始め、調整を依頼したり質問する） |
| 5 | **選択的な承認** | **同じファイル内で一部のハンクだけ承認**できる。気に入った部分を残して他を捨てられる。Kiro は選択的な承認を受けて作業を続け、**好みに適応する** |
| 6 | **Accept All / Reject All** | Accept All は保留中の全変更を適用して実行を続ける／**Reject All は全変更を戻し、別のアプローチのためのフィードバックを入力できる** |

> **Reject All のあとにフィードバックを渡せる**のが要点です。単に捨てるのではなく、
> 「なぜ違うのか」を伝えて別の方向で作り直させられます。

### 5.1 必ずレビュー対象になるファイル操作（7種）

| 操作 | 内容 |
|------|------|
| ファイル作成・上書き | 新規作成、内容の置き換え |
| テキスト置換 | ファイル内の特定のテキストを置換 |
| 内容の追記 | ファイル末尾への追加 |
| ファイル削除 | ワークスペースからの削除 |
| コード編集 | ファイル内のコードの変更 |
| シンボルのリネーム | 変数・関数・クラスを横断的にリネーム |
| ファイルの移動 | 移動と参照の更新 |

**このレビューは Kiro のワークフローに組み込まれており、AI モデルがスキップすることはできません。**

なお、**連続する同一ファイルへの編集はまとめられることがあります**（中断を減らすため）。

## 6. Supervised が「セキュリティ機構ではない」とはどういうことか

公式の警告:

> **Supervised モードはコードレビューのワークフローであり、セキュリティ制御ではありません。**
> **サンドボックス・分離境界・アクセス制御機構としては機能しません。**

**Supervised モードが制限しないもの**:

| 項目 | Supervised でも制限されない |
|------|------------------------|
| **エージェントがどのファイルを読めるか** | 制限されない |
| **どんなコマンドを提案できるか** | 制限されない |
| **どんなネットワークアクセスを持つか** | 制限されない |
| **信頼するコマンド一覧に入れたシェルコマンド** | **別の承認経路**に従う（レビュー対象外） |

**レビュー対象は「Kiro のファイル編集操作を通じた変更」だけ**です。エージェントが実行した bash コマンドがファイルを書き換えた場合、それは追跡されません（[02_chat.md](02_chat.md) §8.1 も参照）。

### 6.1 では何で守るのか

| 手段 | 参照 |
|------|------|
| **権限設定**（capability ベース） | [03_permissions.md](03_permissions.md)・[04_reference/03_permissions.md](../04_reference/03_permissions.md) |
| **保護されたパス** | [03_deployment/05_security.md](../03_deployment/05_security.md#3-保護されたパスprotected-paths) |
| **信頼するコマンドを最小限にする** | [03_deployment/05_security.md](../03_deployment/05_security.md#2-信頼するコマンドtrusted-commands) |
| **`.kiroignore`** でエージェントに見せない | [04_reference/01_kiro-directory.md](../04_reference/01_kiro-directory.md#10-無視ファイル--kiroignore) |
| **ワークスペースの分離・資格情報のスコープ設定** | [03_deployment/05_security.md](../03_deployment/05_security.md#7-公式が挙げるベストプラクティス) |

## 7. 実務での組み合わせ方

公式の記述から導ける使い方です。

| 状況 | 組み合わせ |
|------|----------|
| 慣れないコードベースで作業を始める | **Supervised** ＋ `.kiroignore` で秘密情報を遮断 |
| よく分かっている繰り返し作業 | **Autopilot** ＋ 権限で書き込み範囲を `src/**` などに限定 |
| 機密情報を扱うプロジェクト | **モードによらず**権限の `deny` で読み取りを遮断する（Supervised では守れない） |
| 大きなリファクタリング | **Autopilot** ＋ チェックポイントで戻れるようにしておく |
